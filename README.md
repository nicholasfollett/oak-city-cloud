## How I think about technology

**Boring is a feature.** I reach for proven, well-understood tools first. New technology has to earn its place by solving a real problem, not because it's interesting.

**Simple beats clever.** The best system is the one your team can understand, debug at 2 a.m., and change with confidence. I optimize for clarity over cleverness.

**Own your stack.** You should never be dependent on me. I document decisions, write things down, and hand off work your team can run without me.

**Spend money on purpose.** Cloud makes it easy to overspend quietly. Every recurring cost should be something you chose on purpose.

**Automate the toil, not the judgment.** If something is done by hand more than twice, it probably should be scripted. Decisions that need context stay with people.

**Security and reliability are built in, not bolted on.** Least privilege, backups you've actually tested, and monitoring that tells you something useful are part of the job from day one.

**Honest over agreeable.** If I think an idea is wrong for your situation, I'll say so and explain why, even if that means less work for me.

## How engagements work

1. **Intro call** (free, ~30 minutes). We talk through what you need and whether I'm a good fit.
2. **Proposal.** A written scope, timeline, and price, so there are no surprises.
3. **The work.** Regular check-ins, visible progress, and code and infrastructure in *your* accounts and repositories.
4. **Handoff.** Documentation, a walkthrough, and a clean exit, with optional ongoing support if you want it.
